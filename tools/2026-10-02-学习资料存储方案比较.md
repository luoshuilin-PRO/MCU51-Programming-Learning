# 学习资料存储方案比较

记录日期：2026-10-02。用途：保存编程与电子学习笔记、代码及相关资料。

## 本次决定

优先把比较笔记和学习进度提交 GitHub；Telegram 网盘暂不部署。GitHub 便于查看文本修改历史，但公开仓库不适合保存私人资料、账号凭证或未获授权传播的书籍。版本历史不能代替独立备份，重要内容仍需本地保留副本。

## 方案比较

| 方案 | 适合内容 | 局限 |
|---|---|---|
| GitHub 学习仓库 | Markdown 笔记、代码、练习、进度 | 公开内容任何人可见；不作为大体积视频网盘 |
| Telegram 收藏夹或私有频道 | 文件传递、学习资料的额外副本 | 普通云聊天和频道不是端到端加密；不能保证永久保存 |
| Telegram 网盘开源工具 | 为 Telegram 文件提供网盘界面 | 需要维护应用及登录会话；项目宣传不等于平台保存承诺 |
| 本地电脑与独立备份盘 | 原始资料、私人内容、恢复副本 | 需要主动备份并检查是否能恢复 |

## 查到的项目（仅资料调研，未安装或测试）

- [TeleDrive](https://github.com/herliansyah/teledrive)：项目介绍提供网页文件管理、上传下载及视频播放，使用 Telegram MTProto 接口。项目提醒大量自动化存储可能造成账号限制或数据丢失。
- [TDrive](https://github.com/jeetrex17/TDrive)：桌面应用，使用私有 Telegram 频道组织文件，作者将其定位为学习项目。
- [Teldrive](https://github.com/tgdrive/teldrive)：相关项目入口，未进行功能和安全评估。

这些项目代码在 GitHub，文件存储后端是 Telegram，二者不是同一个存储位置。

## 加密与保留事实

- Telegram 普通云聊天采用客户端与服务器之间的加密，并在服务端加密存储；不等同于只有用户持有密钥的端到端加密。
- 秘密聊天采用端到端加密，但不是跨设备同步的云聊天，不能据此认定 Telegram 网盘也有相同保护。
- 当前隐私政策规定，默认连续 18 个月不登录可触发账号及云端数据删除；用户可在设置中调整期限。“长期可以访问”不等于“永久保存承诺”。
- 需要自行控制文件解密权限时，应在上传前本地加密，并另行保管密钥；本次未配置或验证此流程。
